# Tab Tree 排查指南：重启后为什么看不到树？

适用版本：v0.2.0+。如果你刚安装扩展、重启 Chrome 后发现标签页仍然平铺，请按本文顺序排查。

## 1. 先确认：你看的是 Tab Tree 吗？

Chrome 137+ 自带「垂直标签页」（左侧的标签栏，支持标签组）。它由浏览器绘制，**任何扩展都无法改写它的缩进、层级或样式**。Tab Tree 的树只渲染在自己的侧边栏里。

| | Chrome 原生垂直标签栏 | Tab Tree 侧边栏 |
| --- | --- | --- |
| 顶部 | 标签组名称（如 `feishu`）+ 组内标签 | 蓝色图标 + **Tab Tree** 标题 |
| 搜索 | 没有「Search tabs」输入框 | 有 **Search tabs / 搜索标签页** 输入框 |
| 行内容 | 只有标签标题与关闭按钮 | 标题前有 16px/级缩进与引导线、折叠箭头 |
| 底部 | 新建标签 / 搜索按钮 | `N tabs · M top-level` 状态栏 |
| 能否缩进 | **不能** | 链接打开的子标签自动缩进 |

如果你看到的左侧栏只有标签组和两个平级标签，**那是 Chrome 自带的垂直标签栏，不是 Tab Tree**。这正是最常见的“没有树状继承”原因。

## 2. 打开真正的 Tab Tree 面板

三种方式，任选其一：

1. 点击工具栏上的 **Tab Tree 图标**（如果看不到，点地址栏右侧的拼图图标 → 把 Tab Tree 固定到工具栏）。
2. 安装/更新后自动打开的 **Tab Tree 设置向导**里，点「打开 Tab Tree 侧边栏」。
3. `chrome://extensions` → Tab Tree → 详情 → **扩展程序选项**，打开向导；或直接打开「整页树状视图」。

面板可能在 **右侧**：Chrome 决定扩展侧边栏的位置（`chrome://settings/appearance` → 侧边栏位置），扩展无法强制放左侧。如果 Chrome 原生垂直标签栏占了左侧，Tab Tree 通常会出现在右侧。

## 3. 用设置向导做 30 秒自检

向导页顶部会显示实时树，右侧「Setup check / 安装检查」有五项关键数字：

| 检查项 | 正常值 | 如果不正常 |
| --- | --- | --- |
| Extension version / 扩展版本 | `0.2.0` 或更高 | 版本过旧：重新加载/安装 v0.2.0 |
| Tabs in this window / 当前窗口标签数 | > 0 | 没有标签页，先打开网页 |
| **Tracked link relationships / 已捕获的链接关系** | **> 0** | 见第 4 节 |
| Links restored after restart / 重启后恢复的链接 | 重启后 > 0 | 见第 5 节 |

「已捕获的链接关系」是判断核心：它统计当前浏览器会话里**真实发生过的“页面 A 打开标签 B”事件**。等于 0 时，树必然是平的。

## 4. 已捕获关系为 0 的常见原因

### 4.1 标签页是在安装扩展之前打开的

扩展只能观察安装之后发生的标签创建事件。安装前就已存在的标签没有可信的 opener 记录，会显示为顶级。v0.2.0 会在安装时尽量学习 Chrome 仍保留的 `openerTabId`，但无法保证。

**修正**：在面板里把子标签拖到父标签上（一次拖拽即可，关系会被持久化）。

### 4.2 你是在当前标签页内跳转，而不是“打开新标签”

只有**新标签页**才有父子关系。在 A 页面里点一个普通链接（没有 `target="_blank"`、没有 Ctrl/Cmd+点击）会在 A 内导航，不会创建新标签，因此也不会产生树。

**验证**：在 A 页面里 **Cmd/Ctrl+点击**一个链接，或点带 `target="_blank"` 的链接。新标签应立即缩进到 A 下面。

### 4.3 新标签是浏览器/其他扩展创建的

`Cmd/Ctrl+T`、地址栏、书签、Chrome 恢复的标签、其他扩展用 `chrome.tabs.create` 创建的标签通常没有来源页面，因此是顶级——这是符合设计的行为。

### 4.4 扩展没有运行

`chrome://extensions` 里确认 Tab Tree 已启用且没有红色 **Errors**。点开 “Service worker” 看 Console 是否有异常。v0.2.0 的欢迎页会自动打开；如果没打开，说明安装/更新事件没有跑起来。

## 5. 重启后恢复为 0 / 只有部分关系

v0.2.0 的恢复链路：

1. 每次树变化后，把 `{url, index, parentId}` 快照写入 `chrome.storage.local`。
2. 浏览器重启时 `chrome.storage.session` 被清空，扩展据此判断“这是一次真正的重启”。
3. Chrome 异步恢复标签页；扩展在最多 60 秒内不断用 URL/顺序匹配快照，匹配多少就立即画出多少。
4. 恢复期间 **不会** 用不完整的平树覆盖好快照；service worker 被杀后，下一次唤醒会从 `storage.session` 里的 pending 记录**继续恢复**，而不是当作普通唤醒放弃。

仍不恢复时检查：

- 重启前是否等树已经显示出来（快照有 900ms 防抖；刚打开链接就立刻关 Chrome 可能没落盘）。
- 重启后打开面板：恢复进行中时底部会显示「Restoring tabs… N/M」；即使超过 60 秒，面板也会展示最终匹配结果。
- 面板底部出现「N links restored」但层级不对：这是启发式匹配的边界情况（重复 URL、多窗口、顺序大改）。带 ↺ 徽标的行可以拖拽修正。
- 若底部显示「Restore incomplete」，说明 Chrome 没有恢复全部标签；被恢复的部分仍然会尽量挂回父节点。

## 6. 仍然不行时请提供这些信息

1. `chrome://extensions` 里 Tab Tree 的版本号、是否启用、是否有 Errors。
2. 设置向导「安装检查」的五项数字截图。
3. 复现步骤：A 的 URL、你如何打开 B（普通链接 / Cmd+点击 / Ctrl+T / 其他）、重启前后面板截图。
4. Service worker Console 里 `[tab-tree]` 开头的日志（尤其是 `restored session` / `resuming interrupted restore`）。
